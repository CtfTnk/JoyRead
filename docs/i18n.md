# JoyRead Internationalisation (i18n) Guide

This document covers how the JoyRead localisation system works, how to add a new language, and the conventions every contributor should know.

---

## Overview

JoyRead uses a JSON-based locale system with a module-level singleton (`LocaleService`) that any UI module can call via the `t()` function. Translations live in flat key–value JSON files (stored nested for readability and flattened to dot-separated keys on load).

```
src/joyread/resources/locales/
    en.json          ← English (always loaded as fallback)
    zh.json          ← Chinese (Simplified)
    ja.json          ← Japanese
```

A user can also supply an override file in the support directory — this is checked first, so it wins over the bundled file:

```
~/Library/Application Support/JoyRead/JoyRead/Config/locales/<code>.json
```

---

## Key Concepts

### Locale files

Each file is a nested JSON object. Keys are grouped by UI area:

| Section    | What it covers                                      |
|------------|-----------------------------------------------------|
| `sidebar`  | Sidebar section headings and fixed item labels      |
| `settings` | Settings page labels, banners, and buttons          |
| `menu`     | Context menu and action menu items                  |
| `sort`     | Sort-field dropdown labels                          |
| `tags`     | Tag management page buttons and messages            |
| `state`    | Empty/loading/error state view titles and messages  |
| `dialog`   | Dialog titles, body text, and button labels         |
| `toolbar`  | Toolbar tooltips, search placeholder, and search button labels |
| `reader`   | Reader window controls, settings/custom panels, topic panel, and status text |

Nested keys are flattened to dot-separated strings on load:

```json
{ "sidebar": { "book_shelf": "Book Shelf" } }
```

becomes the key `"sidebar.book_shelf"` at runtime.

### The `t()` function

Import and call from any UI module:

```python
from joyread.infrastructure.i18n.locale_service import t

label = t("sidebar.book_shelf")           # "Book Shelf" / "书架" / "本棚"
msg   = t("dialog.delete_book_msg", title="My Novel")  # supports {placeholder} substitution
```

If a key is missing in the active locale it falls back to English. If it's missing in English too, the raw key string is returned so nothing crashes silently.

### Language codes

Languages are stored in settings as their English name and mapped to ISO 639-1 codes internally:

| Setting value | Display label | Code | File       |
|---------------|---------------|------|------------|
| `"English"`   | `English`     | `en` | `en.json`  |
| `"Chinese"`   | `中文`        | `zh` | `zh.json`  |
| `"Japanese"`  | `日本語`      | `ja` | `ja.json`  |

The setting value stays canonical for compatibility; the dropdown shows the
native display label and maps it back to the canonical value before persisting.

## Adding a New Language

1. **Copy the template** from `docs/locale_template.json` and rename it to your ISO code (e.g. `ko.json` for Korean).

2. **Translate every value.** Leave JSON keys unchanged — only edit the string values.

3. **Mind the `delete` literal rule** (see below).

4. **Place the file** in one of:
   - `src/joyread/resources/locales/ko.json` — bundled with the app
   - `<support-dir>/Config/locales/ko.json` — user-supplied override (takes priority)

5. **Register the language** in `locale_service.py`:

   ```python
   # src/joyread/infrastructure/i18n/locale_service.py

   LANGUAGE_OPTIONS: tuple[LanguageOption, ...] = (
       LanguageOption("English", "en", "English"),
       LanguageOption("Chinese", "zh", "中文"),
       LanguageOption("Japanese", "ja", "日本語"),
       LanguageOption("Korean", "ko", "한국어"),  # ← add this
   )
   ```

   The settings page language dropdown is built from `LANGUAGE_OPTIONS`
   automatically and displays `native_name` while persisting `settings_value`.

## The `delete` Literal Rule

Several dialogs ask the user to type the word **delete** to confirm a destructive action (resetting the library, etc.). The validator always checks:

```python
value.strip().lower() == "delete"
```

This check is **never translated** — users must type the ASCII word `delete` regardless of the active language. The surrounding prompt text _is_ translated, but the word itself must appear literally:

```json
// zh.json
"dialog.type_delete_header": "输入 delete 以确认",
"dialog.type_delete_error":  "请输入 delete 以确认。"

// ja.json
"dialog.type_delete_header": "「delete」と入力して確認",
"dialog.type_delete_error":  "「delete」と入力すると、削除を行います。"
```

When writing a new locale file, keep the word `delete` unchanged inside these two values.

## How Language Changes Propagate at Runtime

Switching language in Settings triggers the following chain:

```
SettingsViewModel.set_language()
  → locale_service.load_language()   ← reloads the JSON for the new locale
  → language_changed.emit()
      → MainWindow._on_language_changed()
            → sidebar.refresh_labels()                   ← fixed sidebar items
            → settings_view.refresh_labels()             ← settings nav + content
            → chrome.refresh_labels()                    ← sort dropdown + tooltips
            → chrome.set_action_menu(...)                ← action/context menus
            → shelf_view.toolbar.refresh_labels()        ← filter/tag-filter tooltips + search panel
            → shelf_view.render()                        ← state views (empty, loading, …)
  → state_changed.emit()             ← settings page re-renders (dropdowns, banners, etc.)
```

Widgets that are rebuilt on every render (menus, settings page items) pick up new strings automatically. Widgets with labels set once in `__init__` (sidebar items, section banners, the top toolbar) are refreshed via their `refresh_labels()` / `set_title()` / `set_label()` methods.

The reader windows (`ReaderWindow` / `NovelReaderWindow`) are a separate case: they are constructed fresh each time a book is opened and are not part of the fan-out above. Because every reader widget calls `t()` while building its UI, an opened reader always reflects the language active at open time, so no `refresh_labels()` plumbing is needed there. Note that `_FitModeButton._OPTIONS` deliberately stores only `ReaderFitMode` enum values (not labels) and derives display text through `_fit_mode_label()` at call time, so the fit-mode labels are never frozen at import.

## Sort Field Labels

The sort dropdown ("Add Time", "Title", "Author") is a special case because the `SortField` enum stores canonical English values used for persistence and ViewModel logic. The chrome widget translates these for display while keeping canonical values in all signals:

```
SortField.ADD_TIME  →  t("sort.add_time")  →  displayed label
user selects label  →  _sort_field_from_label()  →  emits SortField.ADD_TIME.value
```

This means `ShelfViewModel.set_sort()` and the settings persistence layer never see translated strings — they always receive the canonical English value (`"Add Time"`, `"Title"`, `"Author"`).

When a new sort field is added to `SortField`, add a matching key under `"sort"` in every locale file and the template. The key name follows the pattern `sort.<enum_name_lowercased>` — e.g. `SortField.ADD_TIME` → `"sort.add_time"`.

## Architecture Reference

| File | Role |
|------|------|
| `src/joyread/infrastructure/i18n/locale_service.py` | `LocaleService` class, `init()`, `load_language()`, `t()`, `LANGUAGE_OPTIONS` |
| `src/joyread/resources/locales/*.json` | Bundled locale files |
| `docs/locale_template.json` | Template for new languages (copy this) |
| `src/joyread/app/app_context.py` | Calls `locale_service.init()` at startup with the saved language |
| `src/joyread/ui/viewmodels/settings_viewmodel.py` | Calls `locale_service.load_language()` and emits `language_changed` |
| `src/joyread/ui/views/main_window.py` | `_on_language_changed()` — fans out refresh calls to all static-label widgets |
| `src/joyread/ui/widgets/window_chrome.py` | `refresh_sort_labels()` — rebuilds sort dropdown with translated labels |
| `src/joyread/ui/widgets/sidebar.py` | `refresh_labels()` — updates fixed sidebar item text |
| `src/joyread/ui/widgets/settings_page.py` | `SettingsSidebarWidget.refresh_labels()` — updates settings nav text |
