<summary><strong>简体中文 · 欣阅 1.4.1</strong></summary>

界面不再闪出多余的窗口。欣阅 1.4.1 修复了一闪而过的空白窗口和 Windows 上的控制台窗口，让隐藏空间的对话框在处理时留在原处，并说明 macOS 上如何覆盖安装新版本。

### 本次修复

- **不再闪出空白小窗口：** 重建对话框按钮、筛选对话框、标签列表、侧边栏书单、设置页面、阅读器目录与书签以及详情页缩略图时，旧控件有时会作为独立的空白窗口一闪而过，在 Windows 上最明显。
- **Windows 不再闪出控制台窗口：** 阅读 7z、RAR 书籍时，后台解压工具不再弹出控制台窗口。
- **隐藏空间对话框留在原处：** 检查密码或应用修改时，对话框变灰并显示处理中的标题，不再切换到单独的进度面板。隐藏或取消隐藏后，书架原地刷新，不再经过加载状态。
- **ZIP 书籍中的日文和中文名称：** 在日文或中文 Windows 上制作的 ZIP/CBZ 书籍，常以 Shift-JIS、GBK 或 Big5 保存文件夹名和文件名。这些名称在目录中不再显示为乱码，页面也按真实名称排序。书库中已有的书籍下次打开时就会显示正确名称。导入时被重新打包的书籍（例如压缩包里嵌套的压缩包）和已加密到隐藏空间的书籍，需要用原始文件重新导入才会更新。
- **macOS 覆盖安装说明：** DMG 窗口、README 和使用手册都会提示：升级时先退出 JoyRead，Finder 询问时选择**替换**。

### 下载与安装

在本页底部的 **Assets（附件）** 中选择适合系统的安装包：

| 系统 | 安装包 | 要求 |
| --- | --- | --- |
| macOS · Apple Silicon | `JoyRead-1.4.1-macos-arm64.dmg` | macOS 26+，不提供 Intel 版本 |
| Windows · x64 | `JoyRead-1.4.1-windows-x86_64-setup.exe` | Windows 10/11 x86-64 |
| Ubuntu / Linux · amd64 | `JoyRead-1.4.1-linux-amd64.deb` | 基于 Ubuntu 22.04 构建 |
| Ubuntu / Linux · arm64 | `JoyRead-1.4.1-linux-arm64.deb` | 基于 Ubuntu 22.04 构建 |

`SHA256SUMS` 提供安装包校验值；`build-info.json` 记录版本、实际构建提交和逐平台构建来源。Linux 包并不保证兼容所有发行版。

**macOS 首次启动：** 打开 DMG，把 JoyRead 拖进**应用程序**文件夹，再从该文件夹启动。应用使用 ad-hoc 签名，未经过 Apple 公证。如果系统提示无法验证应用，在确认下载来源后：

1. 点击**「完成」**，不要点击「移到废纸篓」。
2. 打开**苹果菜单 → 系统设置 → 隐私与安全性**。
3. 在**「安全性」**中找到 JoyRead 被阻止的提示。
4. 点击**「仍要打开」**，按提示确认或验证身份。

安装新副本后可能需要再次确认。如果 Launchpad 尚未显示，请先从「应用程序」直接打开。

**macOS 升级：** 请先退出 JoyRead，再把新版本拖入「应用程序」，Finder 询问时选择**替换**。选择**保留两者**会留下名为「JoyRead 2」的第二份副本，「打开方式」仍可能选中它。

**Windows：** 运行 EXE 安装程序。安装包没有受信任的代码签名；如果出现 SmartScreen 提示，确认来源后选择**「更多信息 → 仍要运行」**。

**Ubuntu：** 在下载目录打开终端，按架构选择命令。图形安装器可能卡在“正在准备”，请使用 APT：

```bash
# amd64 / x86-64
sudo apt install ./JoyRead-1.4.1-linux-amd64.deb
# arm64
sudo apt install ./JoyRead-1.4.1-linux-arm64.deb
```

### 升级与兼容性

从 1.4.0 升级不新增数据库迁移（仍为第 15 版），保留书库、书单、标签、自定义排序、封面、阅读进度、每本书的阅读设置和隐藏空间。从 1.3.1 或更早版本升级会把书库升级到第 15 版，之后旧版本无法再打开该书库，请先备份书库；旧版隐藏空间中的书籍在首次解锁前保持隐藏但未加密。支持 ZIP/CBZ、7z/CB7、RAR/CBR 和 PDF（带密码的压缩包除外），EPUB 仍未启用。

# JoyRead 1.4.1

No more stray windows. JoyRead 1.4.1 stops blank windows and Windows console windows from flashing up, keeps Hidden Space dialogs in place while they work, and explains how to replace an older copy on macOS.

## What's fixed

- **No more flashing blank windows:** when JoyRead rebuilt dialog buttons, the Filter dialog, tag lists, the sidebar's collections, Settings pages, the Reader's contents and bookmarks, or thumbnails in book details, an old control could briefly appear as a blank window of its own, most visibly on Windows.
- **No console window on Windows:** reading a 7z or RAR book no longer flashes a console window from the extraction helper.
- **Hidden Space dialogs stay in place:** while a passphrase is checked or a change is applied, the dialog greys out under a busy title instead of switching to a separate progress panel. After hiding or unhiding, the shelf refreshes in place instead of passing through its loading state.
- **Japanese and Chinese names in ZIP books:** ZIP/CBZ books made on Japanese or Chinese Windows often store folder and file names in Shift-JIS, GBK or Big5. Those names no longer show as garbled characters in the Contents, and pages sort by the real names. Books already in the Library show the corrected names the next time they open. A book that was repackaged at import, such as an archive nested inside another, or one sealed in Hidden Space, keeps its old names until it is imported again from the original file.
- **Updating on macOS:** the DMG window, the README, and the user manual now say to quit JoyRead first and choose **Replace** when Finder asks.

## Download and install

Choose the package for your platform from **Assets** at the bottom of this page:

| Platform | Installer | Requirements |
| --- | --- | --- |
| macOS · Apple Silicon | `JoyRead-1.4.1-macos-arm64.dmg` | macOS 26+; no Intel build |
| Windows · x64 | `JoyRead-1.4.1-windows-x86_64-setup.exe` | Windows 10/11 x86-64 |
| Ubuntu / Linux · amd64 | `JoyRead-1.4.1-linux-amd64.deb` | Built on Ubuntu 22.04 |
| Ubuntu / Linux · arm64 | `JoyRead-1.4.1-linux-arm64.deb` | Built on Ubuntu 22.04 |

`SHA256SUMS` contains installer checksums; `build-info.json` records the version, actual build commit, and per-target provenance. Linux packages do not imply compatibility with every distribution.

**macOS first launch:** open the DMG, drag JoyRead into **Applications**, and launch it there. The app is ad-hoc signed and not Apple-notarized. If macOS says it cannot verify the app, after verifying your download source:

1. Click **Done**, not **Move to Bin**.
2. Open **Apple menu → System Settings → Privacy & Security**.
3. Find the JoyRead blocked-app notice under **Security**.
4. Click **Open Anyway**, then confirm/authenticate as prompted.

A new copy may require approval again. If Launchpad does not show it, open it directly from Applications first.

**Updating on macOS:** quit JoyRead first, drag the new copy into Applications, and choose **Replace** when Finder asks. **Keep Both** leaves a second copy named “JoyRead 2” that Open With can still pick.

**Windows:** run the EXE installer. It has no trusted code signature; if SmartScreen appears, verify the source before choosing **More info → Run anyway**.

**Ubuntu:** open a terminal in the download folder and choose your architecture. The graphical installer may remain at “Preparing”, so use APT:

```bash
# amd64 / x86-64
sudo apt install ./JoyRead-1.4.1-linux-amd64.deb
# arm64
sudo apt install ./JoyRead-1.4.1-linux-arm64.deb
```

## Upgrade and compatibility

Upgrading from 1.4.0 adds no database migration; the library stays on schema 15. Your library, collections, tags, custom order, covers, reading progress, per-book settings, and Hidden Space are retained. Upgrading from 1.3.1 or earlier moves the library to schema 15, after which earlier versions cannot open it, so back up your library first; books hidden by an earlier version stay hidden but unencrypted until the first unlock. ZIP/CBZ, 7z/CB7, RAR/CBR, and PDF remain supported (except password-protected archives); EPUB remains disabled.
